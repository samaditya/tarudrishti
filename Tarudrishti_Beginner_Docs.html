Tarudrishti

A Beginner's Guide to Understanding the Botanical AI Assistant

👋 Welcome! What is Tarudrishti?

Imagine having a master gardener, a plant pathologist, and a diligent personal assistant available 24/7 in your pocket. That's Tarudrishti. It is a web application (specifically, a Progressive Web App or PWA) that helps you take care of your plants.

You can talk to it normally ("Hey, I watered my snake plant today"), send it pictures of sick leaves, and it will log your actions, diagnose problems, and even email you a schedule of what to do next.

🧠 The Analogy: A Digital Clinic for Plants Think of Tarudrishti as a high-tech hospital for your plants. You walk into the lobby (the Frontend UI), and the receptionist directs you to the right department. If you just need to log a visit, a clerk takes your details. If your plant is sick, you're sent to a specialist doctor. Behind the scenes, the hospital staff securely stores your files and schedules follow-up appointments.
The Tarudrishti Dashboard: Your visual plant clinic.

🛠️ The Tech Stack (The Toolkit)

Every web application is built using a combination of technologies. Here is what we used for Tarudrishti, broken down simply:

⚛️
React & Vite (Frontend)

The buttons, text, and images you see and click on. React builds the interface, and Vite makes it load incredibly fast.

⚡
FastAPI (Backend)

The "brain" of the app. It runs on a server, securely processes your requests, talks to the database, and sends data back to React.

🐘
PostgreSQL (Database)

The filing cabinet. A highly reliable system that stores all your user data, plant names, and care logs securely.

🤖
LangGraph & OpenAI (AI)

The intelligent agents. They read your text or look at your plant photos and figure out exactly what needs to be done.

🧠 Core Concepts Explained

1. Multi-Agent AI System (LangGraph)

Instead of having one giant AI try to do everything (and get confused), Tarudrishti uses a "multi-agent" approach. It breaks tasks down and hands them to specialists. This is managed by a tool called LangGraph.

🚦 The Analogy: The Triage System When you send a message, it first goes to the Router Node (the triage nurse). The nurse looks at your message and says:
  • "I watered my rose" ➡️ Sends you to the Logger Agent (clerk) to update your records.
  • "What is this white spot on my leaf?" (with image) ➡️ Sends you to the Diagnostician Agent (doctor) for a prescription.
  • "How much sunlight do ferns need?" ➡️ Sends you to the Botanist Agent (librarian) for general advice.

2. Semantic Caching (pgvector)

AI can be slow and expensive. If 100 people ask "How often should I water a cactus?", we shouldn't pay the AI to answer it 100 times.

We use pgvector (a feature in our database) to store past questions and answers as "vectors" (mathematical coordinates). When you ask a new question, the system checks: "Have we answered something mathematically similar to this recently?"

🗂️ The Analogy: The FAQ Binder Imagine the Botanist Agent has a binder of Frequently Asked Questions on their desk. Before asking the Head Professor (OpenAI) a question, they quickly flip through the binder. If the answer is there, they give it to you instantly. This saves time and money!

3. JSON and Structured Output

When the Logger Agent reads "I gave my Monstera a cup of water today," it doesn't just reply with text. It extracts the data into a strict format called JSON, which the database understands:

{
  "plant_name": "Monstera",
  "action": "Watering",
  "substance": "Water",
  "date": "2026-05-12"
}

This ensures our app actually functions like a tool, not just a chatbot.

📁 Navigating the Codebase

If you look at the files in this project, it's divided into two main folders. Here is what they do:

The src/ Folder (Frontend)

This is the React code. It runs in the user's web browser.

  • Components: Pieces of the UI, like Lego bricks. For example, PlantCard.jsx is the visual card showing a plant, and AIChatSheet.jsx handles the chatting interface.
  • API Calls: It talks to the backend using a library (often React Query) to fetch your plant data.
  • Image Compression: Before sending a giant 5MB photo to the AI, the frontend shrinks it using the browser's Canvas API so it uploads instantly.

The backend/ Folder (Backend)

This is the Python (FastAPI) code. It runs on a server.

  • main.py: The main entry point. It sets up the server and the API routes (URLs the frontend can call).
  • graph.py: The most complex part! This is where LangGraph is set up, defining the Router, Logger, and Diagnostician agents.
  • models.py: Defines the Database tables (Users, Plants, CareLogs) using a tool called SQLAlchemy.
  • Scheduler: A background process that wakes up every day at 8 AM, checks the database, and emails you if your plant needs watering.
