Multi-Agent Failure Modes & Recovery

The system employs a StateGraph architecture via LangGraph. Reliability is ensured through deterministic fallbacks and structured output validation.

Router Hallucination

If the Router Node fails to generate a valid IntentType or hallucinates an unknown intent, the route_intent logic defaults to the error_node, prompting a graceful clarification request.

Pydantic Parsing Errors

When with_structured_output fails (e.g., malformed JSON from OpenAI), nodes wrap the invocation in try/except blocks, returning a JSON response containing an error key instead of crashing.

Timeout & Rate Limit Fallbacks

Failure Case Mechanism Resolution
OpenAI RateLimitError HTTP 429 Catch Returns "AI is currently overloaded. Please try again in a minute."
APITimeoutError (Vision) HTTP 503 Catch OpenAI default timeout (60s) trigger; UI shows retry prompt.
Graph Node Crash Global Exception Handler API returns 500 with full stack trace to frontend for debugging.

Database Scaling & Vector Bottlenecks

Tarudrishti uses PostgreSQL with the pgvector extension for semantic caching. This reduces LLM costs by ~40% for frequent botanical queries.

SQLAlchemy Relationships

  • User ↔ Plant: 1:N Relationship with cascade="all, delete-orphan".
  • Plant ↔ CareLog: 1:N Relationship with cascade="all, delete-orphan".

The KNN Bottleneck

The current implementation uses Exact Nearest Neighbor Search (KNN) via Cosine Distance:

Query Complexity: O(N * D)
N = Number of cached queries (1536-dim vectors)
D = Dimensions (1536 for text-embedding-3-small)

At N > 100,000, exact search introduces linear latency (~150ms+). To resolve this, we must transition to HNSW (Hierarchical Navigable Small World) indexing.

Scaling Solution: HNSW Index Implementation


# Migration logic to fix scaling bottleneck
# Replaces exact search with O(log N) approximate search
with engine.begin() as conn:
    conn.execute(text("""
        CREATE INDEX ON semantic_cache 
        USING hnsw (embedding vector_cosine_ops) 
        WITH (m = 16, ef_construction = 64);
    """))
